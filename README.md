# Boosty Downloader Web

Серверный загрузчик и частный архив постов Boosty для Linux VPS. Веб-панель доступна по HTTPS, с отдельными учётными записями, регистрацией по разрешению администратора и личными подключениями Boosty. Статус: **первый рабочий прототип**; тестирование с реальным Boosty ещё требуется.

## Возможности первого прототипа

- По ссылке Boosty: проверка поста, список медиа и потоковое скачивание на ПК через VPS.
- Сохранение полной копии поста: HTML + JSON + изображения; опционально видео, аудио, файлы, комментарии с ответами.
- Личный каталог авторов, просмотр комментариев в ветках и видео на странице публикации.
- Просмотр сохранённой HTML-копии по адресу `/library/<job-id>/` через веб-интерфейс после закрытия браузера.
- Личные и общие архивы: адресное приглашение участников **или** публикация для всех зарегистрированных пользователей, поиск по автору/названию, выбор автора, скачивание ZIP.
- У каждой копии независимое поле `archiveUpdatedAt` (дата завершённого снимка) и дата в HTML-странице. Изменение разрешений или состояния задачи не подменяет время обновления архива.
- Удаление одного поста или всех постов автора с подтверждением, а также выборочная автоматическая синхронизация.
- Сначала вход в панель по логину/паролю; регистрация новых пользователей включается администратором. Затем подключение Boosty через cookie `auth` или access token, опционально refresh token + device ID. Токены каждого пользователя шифруются AES-GCM и не передаются другим участникам.
- Фоновая очередь, восстанавливаемая после рестарта, частичная HTTP Range-докачка.
- Нативная установка (Go + systemd) **или** Docker Compose с одними и теми же каталогами данных.
- Запуск по IP или домену, настройка порта, HTTPS с самоподписанным или готовым PEM-сертификатом.

## Установка (как в Firewall-UI)

> **Внимание:** репозиторий пока приватный. Команда `curl https://raw.githubusercontent.com/.../install.sh | bash` без авторизации GitHub **не работает**. Сначала клонируйте репозиторий через `gh auth login` / персональный токен / SSH-ключ.

```bash
gh repo clone SawaMEN/boosty_downloader
cd boosty_downloader
sudo bash install.sh
```

В меню выберите `1) Native` или `2) Docker`, затем IP/домен и сертификат. Для локального доступа можно выбрать `127.0.0.1` и использовать SSH-туннель. По умолчанию порт **8443**.

**Зависимости первой установки:** Linux; `openssl`, `useradd`; для native — systemd и Go 1.23+ (позже будет установка готового релизного бинарника), для Docker — Docker Engine и Compose v2 (Go на VPS не требуется). При переключении режимов повторно запустите `sudo bash install.sh`, выбрав другой вариант.

Без вопросов (для автоматизации, из клона):

```bash
sudo env BD_PUBLIC_HOST=203.0.113.10 BD_PORT=8443 BD_TLS_MODE=selfsigned \
  BD_ADMIN_USER=admin BD_ADMIN_PASSWORD='ChangeMe12345678' bash install.sh --mode native
```

Адрес `203.0.113.10` — пример из документационного диапазона, замените своим реальным IP.

## Управление

```bash
sudo bdy                # Меню управления
sudo bdy status
sudo bdy logs
sudo bdy start
sudo bdy stop
sudo bdy restart
sudo bdy update        # Инструкция по обновлению из нового клона
sudo bdy uninstall     # Удалить службу и приложение, сохранить архив
sudo bdy uninstall --purge  # Также удалить настройки, токены и все архивы (подтверждение)
```

Native и Docker используют:

| Назначение | Путь на хосте |
| --- | --- |
| Конфигурация, пароль, ключ | `/etc/boosty-downloader/environment` |
| Сертификаты | `/etc/boosty-downloader/tls/` |
| Архивы/токены/очередь | `/var/lib/boosty-downloader/` |
| Нативный бинарник | `/usr/local/boosty-downloader/boosty-downloader` |
| Docker-сборка | `/opt/boosty-downloader/` |

### HTTPS

Панель требует HTTPS, включая IP-доступ. Самоподписанный сертификат вызовет предупреждение браузера; для общедоступного домена рекомендуется получить доверенный сертификат, передав его PEM-файлы при установке. Автоматическое продление сертификатов требуется проверить на VPS. Не открывайте административную панель в публичном доступе без надёжного пароля и доверенного сертификата.

Порт на внешнем файрволле хостинга необходимо разрешить вручную. Установщик **не меняет** правила UFW/nftables/iptables и чужие Docker-ресурсы.

## Ограничения и безопасность

- Закрытый контент доступен только пользователям с действующей подпиской/правами доступа. Инструмент не обходит DRM и платные ограничения.
- Для конечных незашифрованных `.m3u8` HLS VOD, включая отдельные AUDIO-группы, и статических `.mpd` DASH VOD (ISO-BMFF SegmentTemplate/Timeline/List) реализована локальная сборка MP4 без сетевых обращений FFmpeg. Live, DRM, byte-range для DASH, мультипериодный DASH, внешние плееры, сложный DraftJS и ограничения комментариев остаются в плане и требуют проверок на живом Boosty. ZIP, удаление/повтор задач и синхронизация реализованы первоначально, но ещё требуют проверки на реальных публикациях и VPS.
- Комментарии могут выдаваться Boosty частично; манифест включает соответствующий статус.
- Не размещайте зашифрованные токены отдельно от ключа на публичном ресурсе; файлы `/etc/boosty-downloader` защищены режимами доступа ОС.
- Рекомендуется делать резервную копию `/etc/boosty-downloader` вместе с `/var/lib/boosty-downloader` (иначе токены не расшифруются).

## Проверка будущей SQLite-миграции

Сервер по-прежнему использует JSON; SQLite доступна только для офлайн-экспорта и проверяемого read-only режима. После остановки службы создать `metadata.db` командой `python3 tools/sqlite_migrate.py --data-dir <путь> --output <путь>/metadata.db`, затем выполнить `go run ./cmd/boosty-dbcheck --data-dir <путь>`. Прежде чем перезапускать сервер, прочитайте [инструкцию и правила отката](docs/DATABASE.md). Переключение рабочих записей на SQLite ещё не поддерживается.

## Общая медиатека

Владелец сохранённого поста открывает **Медиатека → Поделиться** и выбирает:

1. **Всем зарегистрированным** — архив отображается в разделе **Общие архивы** и доступен по автору, названию поста или владельцу.
2. **Отдельному пользователю** — указывает логин участника. Индивидуальное разрешение сохраняется при отключении режима «Всем».

Всё содержимое (HTML, видео, вложения, ZIP) отдаётся сервером только после проверки сессии и прав. Публикация «всем» **не создаёт анонимную публичную ссылку**. Изменить настройки, повторить загрузку и удалить копию вправе только владелец. В карточках показана **дата обновления архива**, которая меняется только после успешной записи снимка (в том числе частичного).

Запросы для интеграций после входа: `GET /api/shared?author=<автор>&q=<название>` и `PUT /api/jobs/{id}/visibility` с JSON `{"everyone":true}` и CSRF-заголовком `X-BD-Request: 1` (только владелец).

> Совместные ZIP включают `index.html`, `manifest.json` и сохранённые медиафайлы. Сырые ответы Boosty и незавершённые `.part`-файлы в переносимый архив не включаются, чтобы не распространять подписанные CDN-ссылки.

## Массовое создание копий из подписок Boosty

После входа **в загрузчик** пользователь подключает **свой аккаунт Boosty**. Сразу после успешного сохранения учётных данных открывается окно **«Создать копии авторов Boosty»**. Его также можно открыть позже из разделов «Авторы» и «Аккаунт Boosty».

1. Список авторов запрашивается у Boosty через `GET /v1/user/subscriptions?limit=100&with_follow=true&offset=...`. В нём могут быть **платные подписки и бесплатные отслеживаемые блоги**. Завершённые и приостановленные администрацией подписки исключаются. Если API не поддерживает нужную постраничную выдачу, интерфейс отмечает неполный список.
2. Выберите авторов с помощью флажков, поиска или «Выбрать всех», затем задайте объём: **20**, **100** или **все доступные** (предохранительный предел **2000** просмотренных публикаций на одного автора). За один запуск можно выбрать до **20 авторов**; остальные — следующим запуском.
3. Подтвердите создание копий. **Само подключение Boosty ничего не загружает.** Для выбранных авторов запускается поиск публикаций по страницам, доступные посты добавляются в очередь. Для каждого поста действуют ваши настройки видео, аудио, файлов, комментариев и повторной синхронизации.
4. В «Авторы → Импорт авторов» виден прогресс поиска, количество добавленных и пропущенных постов. **Завершение поиска не означает, что все медиа скачаны**: статус самих архивов смотрите в «Медиатеке». Импорт можно остановить: уже добавленные задачи останутся в очереди.
5. Данные об импорте (`imports.json`) и очереди (`jobs.json`) хранятся в `/var/lib/boosty-downloader/` и переживают перезапуск нативной службы или Docker. Повторный импорт не создаёт дублей уже известных постов. Подписки и задания каждого пользователя изолированы друг от друга.

Существующий аккаунт Boosty можно отключить, не удаляя свои локальные архивы. После нового подключения окно выбора появится повторно. Список авторов не отправляется другим пользователям.

**Важно:** этот сценарий реализован и покрыт mock-тестами API, но **не проверен на реальном аккаунте Boosty**. Неформально используемый Boosty API может менять формат/пагинацию, а доступ к платным постам всё равно требует активной подписки. Синхронизация по расписанию обновляет уже сохранённые посты и проверяет **новые** публикации выбранных авторов при включённой автопроверке (ограничение 50 последних постов за проход).

API веб-панели после входа: `GET /api/subscriptions`, `POST /api/subscriptions/import` (JSON: `{"authors":["slug"],"maxPosts":20,"includeComments":true,"includeFiles":true,"includeVideos":true,"includeAudio":true,"autoSync":false}`), `GET /api/imports`, `POST /api/imports/{id}/cancel`. Для изменяющих запросов необходим `X-BD-Request: 1`.

### Автопроверка новых публикаций

При выборе авторов после подключения Boosty можно включить «Автосинхронизация». Сервер обновляет уже сохранённые публикации и периодически проверяет новые посты тех авторов, чей последний импорт отмечен для автопроверки. Интервал управляется администратором в **Настройки → Права и автоматизация**; по умолчанию **24 часа**. Переменная `BD_SYNC_INTERVAL_HOURS` используется только при первом запуске для начального значения, далее настройка хранится в `accounts.json`. Значение `0` отключает планировщик полностью.

После первоначального импорта плановая проверка просматривает не более 50 последних постов автора и останавливается при первой ранее известной публикации. Это уменьшает нагрузку на API и диск, но не гарантирует обнаружение старых постов, опубликованных задним числом; для таких случаев запускайте полный импорт вручную. Дубликаты публикаций не создаются. Переключатель автопроверки находится в разделе «Авторы» и доступен только владельцу импорта.

## Проверка целостности архивов

Для вновь скачанных медиа сохраняются SHA-256 и размер в `manifest.json`. При повторной загрузке существующий файл пропускается **только если его контрольная сумма совпадает с манифестом**. Повреждённые файлы загружаются повторно; для старых копий без SHA-256 потребуется переархивация.

В «Медиатеке» у своего готового поста нажмите **«Проверить файлы»**. Сервер проверит размеры и SHA-256 и сообщит, сколько файлов исправно, отсутствует, повреждено или пока не имеет контрольной суммы. Отдельно отображается неполнота снимка из-за ошибок сохранения или ограничений комментариев. Проверка больших архивов читает файлы целиком и может занять время. Исправление — кнопка «Обновить».

Сетевой докачке нужен сильный ETag или корректный Last-Modified от CDN. При отсутствии валидатора скачивание начинается заново; если `If-Range` показывает изменение объекта, старые и новые байты не смешиваются. Неподдерживаемые варианты HLS/DASH, ошибочные ответы CDN и не-медиа содержимое не выдаются за успешно сохранённый MP4; поддерживаемые конечные HLS/DASH собираются локально из сегментов. Ограничение одиночного медиа: 10 ГиБ. Наличие SHA-256 не подтверждает подлинность исходного контента, но обнаруживает локальное повреждение после сохранения.

API (только владелец): `POST /api/jobs/{id}/verify` с `X-BD-Request: 1`. Операция не изменяет дату `archiveUpdatedAt`.


## Панель администратора: политики пользователей и ежедневное архивирование

В **Настройки → Права и автоматизация** администратор устанавливает:

- Разрешение на регистрацию новых участников; по умолчанию регистрация закрыта.
- Общий интервал автоматического поиска новых постов и обновления существующих архивов: **24 часа по умолчанию**, `0` — выключено, допустимо `1–168` часов.
- Максимум публикаций, просматриваемых за плановую проверку одного автора (по умолчанию 50), и максимум при первичном импорте (по умолчанию 2000). Задача поиска новых постов не гарантирует обнаружение публикаций, вставленных в ленту задним числом за пределами окна просмотра.
- Набор разрешений **по умолчанию** для всех обычных пользователей, а затем **индивидуальные исключения**: разрешить, запретить, наследовать для каждого аккаунта.

Отдельно настраиваются подключение к Boosty, просмотр публикаций, воспроизведение/скачивание через VPS, создание архивов, включение комментариев, файлов, видео и аудио, массовая архивация авторов, ежедневная автосинхронизация, выдача личного доступа, публикация архива всем участникам, просмотр общего каталога и удаление архивов. Администратор обладает всеми правами. **По умолчанию обычным пользователям запрещены автоматическая архивация и публикация для всех**, пока администратор явно не разрешит эти функции. Другие разрешения можно изменить там же.

Пользователь самостоятельно выбирает, **каких авторов архивировать и для каких включить проверку новых публикаций**, но только если администратор выдал разрешение `autoArchive`. При отключённом разрешении фоновый планировщик не добавляет новые задания; также отключены изменения соответствующих настроек через API. Войти, просмотреть ранее сохранённые собственные архивы и выйти из Boosty можно независимо от этих разрешений. Публикация «всем» означает **только всех авторизованных участников** сервиса, не анонимный интернет.

После успешной плановой проверки сервер записывает время последнего сканирования (`lastCheckedAt`) в журнале импорта. Дата самого сохранённого поста `archiveUpdatedAt` меняется только после создания нового снимка, а не после проверки отсутствия обновлений. При кратковременной ошибке проверки планировщик предпримет следующую попытку через установленный интервал. Перед загрузкой проверяется, что автор всё ещё присутствует среди активных подписок Boosty; сохранённые ранее посты при этом не удаляются.

API (доступен только администратору): `GET/PUT /api/admin/policy`, `GET /api/admin/users`, `PUT /api/admin/users/{id}/permissions`. Обычный участник получает эффективные разрешения через `GET /api/account`, но сервер **проверяет права отдельно для каждого защищённого действия**, независимо от состояния интерфейса. Управление расписанием доступно через `PUT /api/imports/{id}/schedule` только владельцу архива; включение требует разрешения администратора, отключение — нет.

### Ограничения

В этой итерации один общий интервал для всех участников; отдельные расписания и квоты по каждому пользователю ещё не реализованы. Подключение Boosty через Cookie/токены и обнаружение новых постов нужно проверить на настоящем аккаунте, а также проверить работу после изменения состава подписок и истечения токенов. Изменения в панели не требуют перезапуска службы, но интерфейс уже вошедшего участника должен обновить страницу, чтобы увидеть обновлённые разрешения.


## Экономия места на VPS

- Сжатие сырых текстовых данных Zstandard при сохранении (по умолчанию уровень 3, один поток).
- Дедупликация идентичных медиа по SHA-256 через hardlinks: одно видео может использоваться несколькими архивами без второй физической копии.
- Видео не перекодируется и остаётся доступным для обычного плеера с перемоткой. `index.html` и `manifest.json` не сжимаются.
- Уровень сжатия 0–19 и дедупликация настраиваются **только администратором** в панели управления. Native-установщик устанавливает `zstd`, Docker содержит бинарник `zstd`.
- Ограничения, варианты алгоритмов и план дальнейшей миграции: [docs/STORAGE_COMPRESSION.md](docs/STORAGE_COMPRESSION.md).

### Обработка видео и GPU

Отдельные версии видео создаются только после явного включения в **настройках администратора**. Исходные файлы остаются нетронутыми. Доступны CPU, AMD VA-API (включая Radeon Vega 7), NVIDIA NVENC и Intel QSV с автоматическим пробным кодированием; установка драйверов и проброс GPU должны выполняться на хосте отдельно. Подробная инструкция для native/systemd и Docker: [docs/VIDEO_PIPELINE.md](docs/VIDEO_PIPELINE.md).

### Автоанализ CPU и GPU в панели администратора

При открытии настроек выполняется инвентаризация инструкций CPU, доступных видеоустройств, драйверов и системных программ. Панель показывает подтверждённые и ещё не проверенные возможности FFmpeg, а также рекомендуемые пакеты и настройки для VA-API (AMD), QSV (Intel), NVENC (NVIDIA) и программного режима. Подстановка проверенного профиля в форму не запускает обработку: изменения применяются только при отдельном сохранении администратором. Подробнее — [docs/VIDEO_PIPELINE.md](docs/VIDEO_PIPELINE.md).


### Административные квоты хранилища

Панель администратора показывает физически свободное место и логический размер архива каждого пользователя. Настраиваются минимум свободного места (по умолчанию 1 ГиБ, 0 отключает проверку) и общий лимит архива пользователя (0 — без квоты). Для сетевых загрузок обычных файлов/HLS/DASH проверка выполняется до записи каждой порции; создание MP4 и дополнительной версии FFmpeg требует предварительного резерва. Подробнее: [docs/STORAGE_LIMITS.md](docs/STORAGE_LIMITS.md). Жёсткая изоляция нескольких одновременно работающих FFmpeg требует ограничений диска на уровне ОС.


### Проверка и обновление панели

Администратор настраивает канал `stable` или `dev`, интервал проверки и разрешение автоустановки (по умолчанию выключено). Отдельный root-owned systemd timer обновляет панель вне веб-сервера, сверяет SHA-256, сохраняет предыдущую версию, проверяет `/healthz` и откатывается при ошибке. Поддерживаются native/systemd и Docker. Для приватного GitHub нужна авторизация `gh` на VPS. Подробнее: [docs/UPDATES.md](docs/UPDATES.md). Если стабильных релизов нет, `stable` не применяет обновление.


### Корзина и автоматическая очистка

Удалённые копии находятся в корзине и могут быть восстановлены владельцем без восстановления прежних разрешений общего доступа. В настройках администратора есть срок хранения (1–3650 дней), переключатель автоматической очистки, кнопка очистки просроченных архивов и журнал. **По умолчанию автоматическая очистка выключена, срок 30 дней.** При включении процесс проверяет просроченные копии каждый час и при запуске сервиса, удаляя не более 20 за проход. Физическое освобождение места происходит только после окончательного удаления.


### Уровни подписки и история постов

После сохранения поста программа записывает уровень подписки, полученный **для вашего аккаунта** из списка Boosty, если эти данные доступны. Это снимок подписки на момент проверки, а не утверждение, что пост требовал именно такой уровень: Boosty может менять доступ ко времени, выдавать платные посты отдельно, а часть материалов бывает бесплатной. Уровень другого участника недоступен в общем каталоге и общем экспорте. Два аккаунта с разными подписками сохраняют раздельные права и записи, однако одинаковые проверенные видео и другие медиа на одном разделе физически хранятся единожды через SHA-256 и hardlinks.

При обновлении публикации сохраняется прежняя архивная версия. В личной медиатеке кнопка «История версий» открывает предыдущие копии с просмотром и восстановлением. До 8 старых снимков, без повторного копирования видео. Восстановление отменяет прежний общий доступ и автоматическую синхронизацию, чтобы не открыть данные новой аудитории случайно.
