# Boosty Downloader Web

Серверный загрузчик и частный архив постов Boosty для Linux VPS. Веб-панель доступна по HTTPS, с отдельными учётными записями, регистрацией по разрешению администратора и личными подключениями Boosty. Статус: **первый рабочий прототип**; тестирование с реальным Boosty ещё требуется.

## Возможности первого прототипа

- По ссылке Boosty: проверка поста, список медиа и потоковое скачивание на ПК через VPS.
- Сохранение полной копии поста: HTML + JSON + изображения; опционально видео, аудио, файлы, комментарии с ответами.
- Личный каталог авторов, просмотр комментариев в ветках и видео на странице публикации.
- Просмотр сохранённой HTML-копии по адресу `/library/<job-id>/` через веб-интерфейс после закрытия браузера.
- Личные и общие архивы: адресное приглашение участников **или** публикация для всех зарегистрированных пользователей, поиск по автору/названию, выбор автора, скачивание ZIP.
- У каждой копии независимое поле `archiveUpdatedAt` (дата завершённого снимка) и дата в HTML-странице. Изменение разрешений или состояния задачи не подменяет время обновления архива.
- Удаление одного поста или всех постов автора с подтверждением, а также выборочная автоматическая синхронизация.
- Сначала вход в панель по логину/паролю; регистрация новых пользователей включается администратором. Затем подключение Boosty через cookie `auth` или access token, опционально refresh token + device ID. Токены каждого пользователя шифруются AES-GCM и не передаются другим участникам.
- Фоновая очередь, восстанавливаемая после рестарта, частичная HTTP Range-докачка.
- Нативная установка (Go + systemd) **или** Docker Compose с одними и теми же каталогами данных.
- Запуск по IP или домену, настройка порта, HTTPS с самоподписанным или готовым PEM-сертификатом.

## Установка (как в Firewall-UI)

> **Внимание:** репозиторий пока приватный. Команда `curl https://raw.githubusercontent.com/.../install.sh | bash` без авторизации GitHub **не работает**. Сначала клонируйте репозиторий через `gh auth login` / персональный токен / SSH-ключ.

```bash
gh repo clone SawaMEN/boosty_downloader
cd boosty_downloader
sudo bash install.sh
```

В меню выберите `1) Native` или `2) Docker`, затем IP/домен и сертификат. Для локального доступа можно выбрать `127.0.0.1` и использовать SSH-туннель. По умолчанию порт **8443**.

**Зависимости первой установки:** Linux; `openssl`, `useradd`; для native — systemd и Go 1.23+ (позже будет установка готового релизного бинарника), для Docker — Docker Engine и Compose v2 (Go на VPS не требуется). При переключении режимов повторно запустите `sudo bash install.sh`, выбрав другой вариант.

Без вопросов (для автоматизации, из клона):

```bash
sudo env BD_PUBLIC_HOST=203.0.113.10 BD_PORT=8443 BD_TLS_MODE=selfsigned \
  BD_ADMIN_USER=admin BD_ADMIN_PASSWORD='ChangeMe12345678' bash install.sh --mode native
```

Адрес `203.0.113.10` — пример из документационного диапазона, замените своим реальным IP.

## Управление

```bash
sudo bdy                # Меню управления
sudo bdy status
sudo bdy logs
sudo bdy start
sudo bdy stop
sudo bdy restart
sudo bdy update        # Инструкция по обновлению из нового клона
sudo bdy uninstall     # Удалить службу и приложение, сохранить архив
sudo bdy uninstall --purge  # Также удалить настройки, токены и все архивы (подтверждение)
```

Native и Docker используют:

| Назначение | Путь на хосте |
| --- | --- |
| Конфигурация, пароль, ключ | `/etc/boosty-downloader/environment` |
| Сертификаты | `/etc/boosty-downloader/tls/` |
| Архивы/токены/очередь | `/var/lib/boosty-downloader/` |
| Нативный бинарник | `/usr/local/boosty-downloader/boosty-downloader` |
| Docker-сборка | `/opt/boosty-downloader/` |

### HTTPS

Панель требует HTTPS, включая IP-доступ. Самоподписанный сертификат вызовет предупреждение браузера; для общедоступного домена рекомендуется получить доверенный сертификат, передав его PEM-файлы при установке. Автоматическое продление сертификатов требуется проверить на VPS. Не открывайте административную панель в публичном доступе без надёжного пароля и доверенного сертификата.

Порт на внешнем файрволле хостинга необходимо разрешить вручную. Установщик **не меняет** правила UFW/nftables/iptables и чужие Docker-ресурсы.

## Ограничения и безопасность

- Закрытый контент доступен только пользователям с действующей подпиской/правами доступа. Инструмент не обходит DRM и платные ограничения.
- Видео HLS/DASH, внешние плееры, сложный формат DraftJS и получение всех ответов при API-лимитах — пункты следующего этапа. ZIP, удаление/повтор задач и синхронизация реализованы первоначально, но ещё требуют проверки на реальных публикациях и VPS.
- Комментарии могут выдаваться Boosty частично; манифест включает соответствующий статус.
- Не размещайте зашифрованные токены отдельно от ключа на публичном ресурсе; файлы `/etc/boosty-downloader` защищены режимами доступа ОС.
- Рекомендуется делать резервную копию `/etc/boosty-downloader` вместе с `/var/lib/boosty-downloader` (иначе токены не расшифруются).

## Общая медиатека

Владелец сохранённого поста открывает **Медиатека → Поделиться** и выбирает:

1. **Всем зарегистрированным** — архив отображается в разделе **Общие архивы** и доступен по автору, названию поста или владельцу.
2. **Отдельному пользователю** — указывает логин участника. Индивидуальное разрешение сохраняется при отключении режима «Всем».

Всё содержимое (HTML, видео, вложения, ZIP) отдаётся сервером только после проверки сессии и прав. Публикация «всем» **не создаёт анонимную публичную ссылку**. Изменить настройки, повторить загрузку и удалить копию вправе только владелец. В карточках показана **дата обновления архива**, которая меняется только после успешной записи снимка (в том числе частичного).

Запросы для интеграций после входа: `GET /api/shared?author=<автор>&q=<название>` и `PUT /api/jobs/{id}/visibility` с JSON `{"everyone":true}` и CSRF-заголовком `X-BD-Request: 1` (только владелец).

> Совместные ZIP включают `index.html`, `manifest.json` и сохранённые медиафайлы. Сырые ответы Boosty и незавершённые `.part`-файлы в переносимый архив не включаются, чтобы не распространять подписанные CDN-ссылки.

## Массовое создание копий из подписок Boosty

После входа **в загрузчик** пользователь подключает **свой аккаунт Boosty**. Сразу после успешного сохранения учётных данных открывается окно **«Создать копии авторов Boosty»**. Его также можно открыть позже из разделов «Авторы» и «Аккаунт Boosty».

1. Список авторов запрашивается у Boosty через `GET /v1/user/subscriptions?limit=100&with_follow=true&offset=...`. В нём могут быть **платные подписки и бесплатные отслеживаемые блоги**. Завершённые и приостановленные администрацией подписки исключаются. Если API не поддерживает нужную постраничную выдачу, интерфейс отмечает неполный список.
2. Выберите авторов с помощью флажков, поиска или «Выбрать всех», затем задайте объём: **20**, **100** или **все доступные** (предохранительный предел **2000** просмотренных публикаций на одного автора). За один запуск можно выбрать до **20 авторов**; остальные — следующим запуском.
3. Подтвердите создание копий. **Само подключение Boosty ничего не загружает.** Для выбранных авторов запускается поиск публикаций по страницам, доступные посты добавляются в очередь. Для каждого поста действуют ваши настройки видео, аудио, файлов, комментариев и повторной синхронизации.
4. В «Авторы → Импорт авторов» виден прогресс поиска, количество добавленных и пропущенных постов. **Завершение поиска не означает, что все медиа скачаны**: статус самих архивов смотрите в «Медиатеке». Импорт можно остановить: уже добавленные задачи останутся в очереди.
5. Данные об импорте (`imports.json`) и очереди (`jobs.json`) хранятся в `/var/lib/boosty-downloader/` и переживают перезапуск нативной службы или Docker. Повторный импорт не создаёт дублей уже известных постов. Подписки и задания каждого пользователя изолированы друг от друга.

Существующий аккаунт Boosty можно отключить, не удаляя свои локальные архивы. После нового подключения окно выбора появится повторно. Список авторов не отправляется другим пользователям.

**Важно:** этот сценарий реализован и покрыт mock-тестами API, но **не проверен на реальном аккаунте Boosty**. Неформально используемый Boosty API может менять формат/пагинацию, а доступ к платным постам всё равно требует активной подписки. Синхронизация по расписанию сейчас обновляет уже сохранённые посты; автоматический поиск **новых** публикаций ранее выбранного автора ещё запланирован.

API веб-панели после входа: `GET /api/subscriptions`, `POST /api/subscriptions/import` (JSON: `{"authors":["slug"],"maxPosts":20,"includeComments":true,"includeFiles":true,"includeVideos":true,"includeAudio":true,"autoSync":false}`), `GET /api/imports`, `POST /api/imports/{id}/cancel`. Для изменяющих запросов необходим `X-BD-Request: 1`.

### Автопроверка новых публикаций

При выборе авторов после подключения Boosty можно включить «Автосинхронизация». Сервер обновляет уже сохранённые публикации и периодически проверяет новые посты тех авторов, чей последний импорт отмечен для автопроверки. Интервал задаёт `BD_SYNC_INTERVAL_HOURS` (по умолчанию 12 часов, `0` отключает).

После первоначального импорта плановая проверка просматривает не более 50 последних постов автора и останавливается при первой ранее известной публикации. Это уменьшает нагрузку на API и диск, но не гарантирует обнаружение старых постов, опубликованных задним числом; для таких случаев запускайте полный импорт вручную. Дубликаты публикаций не создаются. Переключатель автопроверки находится в разделе «Авторы» и доступен только владельцу импорта.
