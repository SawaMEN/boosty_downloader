# Boosty Downloader

Веб-панель для сохранения доступных вашему аккаунту публикаций Boosty на собственном Linux-сервере. Есть личные архивы, медиатека, история версий, импорт публикаций авторов и управление доступом.

**Статус:** проект в разработке. Поддержка отдельных форматов Boosty требует проверки на реальных публикациях. Не используйте его как единственную копию важных данных.

## Установка одной командой

На VPS с Linux и systemd выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/SawaMEN/boosty_downloader/main/install.sh | sudo bash
```

Команда сразу запускает установщик **от root через sudo**. Установщик предложит выбрать **Native (рекомендуется, без Docker)** либо Docker, указать IP или домен, порт и способ получения HTTPS-сертификата. Учётная запись администратора создаётся автоматически; случайный пароль показывается один раз. Для установки не нужны GitHub-токен и предварительное клонирование.

Для установки без вопросов:

```bash
curl -fsSL https://raw.githubusercontent.com/SawaMEN/boosty_downloader/main/install.sh | \
  sudo BD_PUBLIC_HOST=203.0.113.10 BD_PORT=8443 BD_TLS_MODE=selfsigned bash -s -- --mode native
```

Замените `203.0.113.10` на настоящий IP. Для домена используйте `BD_PUBLIC_HOST=archive.example.com BD_TLS_MODE=letsencrypt`: домен должен указывать на VPS, а порт **80/TCP** должен быть доступен для получения сертификата. Порт панели (по умолчанию **8443/TCP**) откройте в настройках файрволла самостоятельно.

Установщик сначала загружает готовый бинарник из GitHub Releases с проверкой SHA-256: стабильный `vX.Y.Z`, а если стабильного релиза нет — последнюю прошедшую CI предварительную сборку `edge-...`. Если готовых бинарников ещё нет, он собирает приложение из исходников (при необходимости установит официальный Go с проверкой SHA-256). Docker собирается из исходников в отдельном образе.

Проверить скрипт перед запуском можно по ссылке [install.sh](install.sh).

## Что умеет

- Сохранять посты, изображения, вложения, комментарии, доступные видео и аудио.
- Создавать личную медиатеку, искать публикации и скачивать сохранённые материалы.
- Импортировать доступные посты авторов и отслеживать обновления.
- Хранить историю архивов, восстанавливать версии, использовать корзину.
- Делиться архивом с выбранными пользователями либо всеми зарегистрированными участниками.
- Экономить место через Zstandard и дедупликацию медиа по SHA-256.
- Управлять пользователями, квотами, загрузками и обновлениями из панели администратора.

Проект **не обходит DRM, платные ограничения или права доступа Boosty**.

## Управление сервером

```bash
sudo bdy                  # Меню
sudo bdy status           # Состояние
sudo bdy logs             # Журнал
sudo bdy restart          # Перезапуск
sudo bdy reset-password   # Новый пароль администратора
sudo bdy update           # Проверить обновления
sudo bdy update --apply   # Установить обновление
sudo bdy rollback         # Вернуть предыдущую версию, если сохранена
sudo bdy uninstall        # Удалить приложение, сохранив данные
```

Для смены Native ↔ Docker повторно запустите установщик с `--mode native` или `--mode docker`. При обновлении сохраняются настройки, сертификаты и архивы. **Перед обновлениями и переключением режимов сделайте резервную копию.**

## Файлы и резервное копирование

| Путь | Назначение |
| --- | --- |
| `/etc/boosty-downloader/` | Настройки, HTTPS-ключ, ключ шифрования |
| `/var/lib/boosty-downloader/` | Архивы, медиа, версии, токены и метаданные |
| `/usr/local/boosty-downloader/` | Бинарник Native |
| `/opt/boosty-downloader/` | Проект Docker |
 
Останавливайте сервис и сохраняйте **оба первых каталога вместе**. Без ключа из конфигурации защищённые токены не расшифровать. Не загружайте секреты или резервные копии в GitHub.

## Выпуски и обновления

[Скачать готовые бинарники](https://github.com/SawaMEN/boosty_downloader/releases) — Linux `amd64` и `arm64`, вместе с `SHA256SUMS`.

- **Stable:** релизы с тегами `vX.Y.Z`.
- **Preview:** автоматически публикуются после успешного CI ветки `main` с тегами `edge-<коммит>`. Это сборки для тестирования.
- **Автообновление:** проверяется на хосте по таймеру; автоматическое применение по умолчанию выключено. GitHub CLI и GitHub-токен не нужны ни для stable, ни для preview.

Подробности: [Обновления](docs/UPDATES.md).

## Ограничения

HTTPS обязателен. Для доверенного сертификата используйте домен с Let's Encrypt или собственную PEM-пару. Некоторые HLS/DASH-видео, DRM и изменения API Boosty могут не поддерживаться. Аппаратное ускорение требует соответствующего GPU, драйвера и настройки хоста.

**Основная база пока JSON.** SQLite доступна для проверки и экспериментальной синхронизации, но не используется как основное хранилище или источник прав доступа.
