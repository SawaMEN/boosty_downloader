# Boosty Downloader

**Самостоятельно размещаемый загрузчик и архив публикаций Boosty** с веб-панелью для Linux-сервера. Поддерживает отдельные учётные записи, приватную медиатеку, сохранение публикаций и управление обновлениями.

**Статус:** разрабатываемый прототип. Сборка, тесты и установка проверяются в CI; совместимость со всеми форматами и изменениями API реального Boosty **не гарантируется**. Для важных архивов нужны резервные копии.

## Возможности

- **Архив публикаций:** HTML-страница, JSON, изображения, комментарии, видео, аудио и вложения (доступность зависит от исходной публикации и прав аккаунта).
- **Личные учётные записи:** разные пользователи подключают собственные сессии Boosty и сохраняют независимые архивы.
- **Общий доступ:** разрешение конкретным зарегистрированным пользователям или публикация в общей медиатеке для всех зарегистрированных участников. Доступ анонимных посетителей не включается.
- **Архив авторов:** импорт доступных публикаций из подписок, отслеживание новых постов и выборочная синхронизация.
- **История версий:** сохранение предыдущих копий поста, просмотр и восстановление; до восьми исторических снимков на архив.
- **Экономия диска:** сжатие текстовых файлов Zstandard, дедупликация одинаковых медиа по SHA-256 и hardlinks (при поддержке файловой системы).
- **Видео:** HTTP Range, обработка отдельных HLS/DASH VOD и локальная сборка MP4; опциональная поддержка VA-API/QSV/NVENC в зависимости от драйверов.
- **Администрирование:** пользователи, регистрация, квоты, корзина, удаление и очистка архивов, политики хранения, диагностика хранилища и обновлений.
- **Развёртывание:** native + systemd или Docker Compose; оба режима используют одни и те же каталоги данных и сертификатов.

Проект **не обходит DRM, платные уровни доступа или ограничения Boosty**. Сохраняются только данные, которые доступны подключённому аккаунту.

## Требования

| Требование | Native | Docker |
| --- | --- | --- |
| ОС | Linux с systemd | Linux с systemd |
| Архитектура | x86-64 или ARM64 | x86-64 или ARM64 |
| Go | Для сборки из исходников; установщик может скачать официальный Go с проверкой SHA-256 | На VPS не нужен |
| Docker Engine + Compose v2 | Не требуется | Требуется; на Debian/Ubuntu установщик пытается установить системные пакеты |
| HTTPS | Обязателен | Обязателен |
| Рекомендация | Debian 12+/Ubuntu LTS, несколько ГБ свободного диска | Debian 12+/Ubuntu LTS, достаточно места для образа |

Для готового native-релиза Go не требуется. Если релизных бинарников нет, установщик собирает **текущие исходники**; для этого необходим доступ в интернет к GitHub и Go-модулям. Для обработки отдельных видеоформатов может понадобиться FFmpeg. Для аппаратного ускорения — драйверы и соответствующие устройства на хосте.

## Быстрая установка

<text>Скачайте установщик из публичного GitHub, при необходимости изучите его содержимое и запустите:</text>

```bash
curl -fsSLo install.sh https://raw.githubusercontent.com/SawaMEN/boosty_downloader/main/install.sh
less install.sh
sudo bash install.sh
```

Скрипт предложит **native** или **Docker**, адрес панели (**IP, домен либо localhost**), порт и вариант HTTPS. Если рядом с `install.sh` нет файлов проекта, исходники автоматически скачиваются из публичного репозитория. Регистрация новых пользователей управляется администратором панели.

Вы также можете установить из клона:

```bash
git clone https://github.com/SawaMEN/boosty_downloader.git
cd boosty_downloader
sudo bash install.sh --mode native
# либо
sudo bash install.sh --mode docker
```

### Установка без вопросов

Например, native на конкретном IP с самоподписанным сертификатом:

```bash
sudo env BD_PUBLIC_HOST=203.0.113.10 BD_PORT=8443 \
  BD_TLS_MODE=selfsigned BD_ADMIN_USER=admin \
  bash install.sh --mode native
```

`203.0.113.10` — документационный адрес; замените его IP своего VPS. Если `BD_ADMIN_PASSWORD` не задан, создаётся случайный пароль, который выводится **один раз** при первоначальной установке.

Для домена с Let's Encrypt:

```bash
sudo env BD_PUBLIC_HOST=archive.example.com BD_PORT=8443 \
  BD_TLS_MODE=letsencrypt bash install.sh --mode native
```

Перед выпуском сертификата DNS домена должен указывать на сервер, а **TCP 80** — быть доступным для Let's Encrypt. Порт панели (здесь **8443/TCP**) откройте в файрволле и панели VPS самостоятельно. Установщик не изменяет правила UFW, nftables или iptables.

### Способы HTTPS

- `selfsigned` — самоподписанный сертификат с SAN для указанного IP/домена. Браузер покажет предупреждение.
- `existing` — ваши PEM-файлы: задайте `BD_EXISTING_CERT` и `BD_EXISTING_KEY`. Установщик проверяет сертификат, ключ и соответствие пары.
- `letsencrypt` — сертификат для публичного домена; при использовании systemd настраивается таймер продления.

Панель работает **только по HTTPS**, включая локальный режим `https://127.0.0.1:8443/`.

### Другие параметры установщика

| Параметр | Назначение |
| --- | --- |
| `--mode native`, `--mode docker` | Выбор варианта без меню |
| `BD_SOURCE_REF` | Ветка или тег исходников при загрузке одним скриптом, по умолчанию `main` |
| `BD_BUILD_FROM_SOURCE=1` | Принудительная сборка native из исходников |
| `BD_RELEASE_TAG=vX.Y.Z` | Конкретный опубликованный native-релиз |
| `BD_NATIVE_BINARY` + `BD_NATIVE_SHA256` | Установка собственного бинарника с проверкой контрольной суммы |
| `BD_VIDEO_ACCEL=none/amd/intel/nvidia` | Дополнительные зависимости и устройства для видеоускорения |

Установка повторно **не генерирует** пароль, секретный ключ или TLS-сертификат, если они уже существуют. При обновлении сначала готовится новая версия, затем проверяется её запуск; при неудаче выполняется попытка вернуть предыдущую. **Перед обновлением сделайте резервную копию данных**, особенно если переходите между режимами.

## Управление

После установки доступна команда `bdy`:

```bash
sudo bdy                  # Интерактивное меню
sudo bdy status           # Состояние сервиса
sudo bdy logs             # Логи
sudo bdy restart          # Перезапуск
sudo bdy stop
sudo bdy start
sudo bdy reset-password   # Новый пароль администратора
sudo bdy update           # Проверить наличие обновлений
sudo bdy update --apply   # Применить доступное обновление вручную
sudo bdy rollback         # Откатить обновление, если сохранена предыдущая версия
sudo bdy uninstall        # Удалить программу, сохранив данные
```

`sudo bdy uninstall --purge` **необратимо удаляет архивы, токены и настройки** после дополнительного текстового подтверждения. В обычном режиме удаления данные сохраняются.

Канал **stable** использует публичные GitHub Releases и не требует `gh auth login`. Канал **dev** использует артефакты успешных CI-сборок и требует авторизованный GitHub CLI (`sudo gh auth login`). Автоматическое **применение** обновлений по умолчанию выключено; проверки выполняет root-owned systemd-таймер, а не веб-процесс. Подробности: [UPDATES.md](docs/UPDATES.md).

## Где находятся данные

| Путь | Содержимое |
| --- | --- |
| `/etc/boosty-downloader/environment` | Настройки, ключ шифрования и начальные реквизиты администратора |
| `/etc/boosty-downloader/tls/` | Сертификат и приватный ключ |
| `/var/lib/boosty-downloader/` | JSON-метаданные, архивы, версии, медиа, защищённые токены |
| `/usr/local/boosty-downloader/` | Native-бинарник |
| `/opt/boosty-downloader/` | Docker Compose и контекст сборки |
| `/usr/local/bin/bdy` | Менеджер установки |

**Резервное копирование:** сохраняйте **вместе** `/etc/boosty-downloader/` и `/var/lib/boosty-downloader/` при остановленной службе. Без `BD_SECRET_KEY` из конфигурации зашифрованные токены не восстановить. Не публикуйте эти каталоги, дампы `accounts.json`, файлы `vault/` и резервные копии в GitHub.

## Пользователи, архивы и видео

Владелец публикации может выбрать, кому открыть её в медиатеке: конкретному зарегистрированному пользователю или всем зарегистрированным. Пользователи с разными подписками сохраняют независимые архивы. Одинаковый проверенный файл может физически храниться один раз через hardlinks, но **это не объединяет права доступа**.

Для видео предусмотрены профили CPU и аппаратного ускорения. AMD/Intel используют `/dev/dri` при наличии VA-API/QSV, NVIDIA — драйверы и NVIDIA Container Toolkit в Docker. Совместимость кодеков зависит от видеокарты и драйвера. Инструкции: [VIDEO_PIPELINE.md](docs/VIDEO_PIPELINE.md), [STORAGE_COMPRESSION.md](docs/STORAGE_COMPRESSION.md), [STORAGE_LIMITS.md](docs/STORAGE_LIMITS.md).

Форматы live-трансляций, DRM, часть сложных вариантов DASH/HLS и изменения API Boosty могут не поддерживаться. Не считайте неполную загрузку успешным архивом без проверки манифеста и файлов.

## SQLite: текущий статус

**Основное хранилище сейчас JSON.** Переключение рабочего API на SQLite ещё не завершено. Имеются офлайн-экспорт, проверка целостности, опциональный `BD_SQLITE_SHADOW=1` для зеркалирования оперативных метаданных и инструменты проверки/переиндексации истории. **Shadow не становится источником прав доступа и не заменяет резервное копирование.**

Выполняйте операции с SQLite только на **остановленном сервере** и с проверенной резервной копией. Команды, ограничения и процедура: [DATABASE.md](docs/DATABASE.md).

## Диагностика

```bash
sudo bdy status
sudo bdy logs
sudo systemctl status boosty-downloader.service  # native
sudo docker compose --project-directory /opt/boosty-downloader \
  -f /opt/boosty-downloader/compose.yaml ps       # Docker без GPU-overlay
curl -kfsS https://127.0.0.1:8443/healthz         # замените порт, если меняли его
```

Если панель недоступна, проверьте DNS/IP, правила файрволла, сертификат, занят ли порт, и логи. В Docker дополнительно проверьте `docker compose` и разрешения `/var/lib/boosty-downloader`. Не размещайте Docker socket, root-токен GitHub или секреты в веб-контейнере.

## Разработка

```bash
go mod download
go vet ./...
go test -race ./...
go build ./cmd/boosty-downloader ./cmd/boosty-dbcheck
bash -n install.sh deploy/boosty-downloader-manager deploy/boosty-auto-update
```

В репозитории имеются тесты миграций SQLite, проверки приватности архивов, веб-контракты и CI для Linux AMD64/ARM64. Это не заменяет проверки загрузок на реальном Boosty и полном VPS. Перед сообщением об ошибке проверьте актуальную ветку, результаты GitHub Actions и приложите обезличенные журналы **без cookie, токенов и паролей**.
