# Видео и аппаратное ускорение Boosty Downloader

Обновлено: 10 ноября 2026. Архитектурный ориентир — [Immich](https://github.com/immich-app/immich), его [видеонастройки](https://docs.immich.app/administration/system-settings/) и [GPU-обработка](https://docs.immich.app/features/hardware-transcoding/). Код не копируется: реализация написана для локального Go-сервера и исходных прав Boosty.

## Что уже работает

- Дополнительные версии **локально сохранённых прямых видеофайлов** через FFmpeg. Посты сохраняются в исходном виде, исходники не удаляются, восстановить оригинал можно независимо от FFmpeg.
- Два кодека вывода: H.264 (совместимость) и HEVC/H.265 (при поддержке браузера); не включаем AV1 на Vega 7, где нет аппаратного AV1-энкодера.
- Четыре реализации: `cpu` (libx264/libx265), `vaapi` (AMD), `qsv` (Intel), `nvenc` (NVIDIA), а также режим `auto` и опциональный переход на CPU.
- Проверяется фактическое создание одного тестового кадра каждым backend; наличие `/dev/dri` или кода `h264_vaapi` в `ffmpeg -encoders` **само по себе не гарантирует готовность**.
- Фоновый одиночный worker, безопасный временный `.part.mp4`, SHA-256 и отдельная запись производного файла в манифест. Можно вручную поставить в очередь видео любого пользователя из панели администратора либо включить автоматическое создание для завершённых архивов.
- Качество 16–40 (меньше — лучше качество и больше размер), ограничение высоты 0/720/1080/1440/2160, сохранение только уменьшившихся файлов (опционально); датой оригинального снимка транскодирование не считается.
- Генерация обновлённой автономной HTML-страницы при наличии исходных JSON и комментариев. Отсутствие возможности перестроить HTML не удаляет рабочую оригинальную копию.

*Ограничения*: **HLS/DASH** требует отдельного сегментного загрузчика; транскодер работает только с завершёнными локальными файлами. HDR→SDR tone mapping, аппаратное декодирование и многопоточное распределение очереди **пока не реализованы**. Встроенная диагностика проверяет кодирование; декодирование по умолчанию программное, что уменьшает риск проблем с драйверами. После аварийного завершения задача восстанавливается при включённой автоматической обработке; ручную операцию можно запустить повторно.

## Ryzen 5 5600H / Radeon Vega 7: Debian и Ubuntu

Рекомендуемый вариант — **H.264 + VA-API**, исходное разрешение или 1080p, качество 26. Cezanne/Vega использует VCN и поддерживает аппаратное кодирование H.264/HEVC в зависимости от драйвера и сборки; AV1 аппаратно не поддерживается. Проверяйте точную доступность через `vainfo` и пробное кодирование.

Для существующего **native/systemd** либо при установке через `BD_VIDEO_ACCEL=amd sudo -E bash install.sh --mode native`:

```bash
sudo bash deploy/boosty-video-deps amd
sudo systemctl restart boosty-downloader
```

Помощник устанавливает `ffmpeg`, `vainfo`, `mesa-va-drivers`, а на Debian при наличии репозитория — `firmware-amd-graphics`; добавляет пользователя службы в группы `render`/`video`. На Ubuntu прошивка AMD обычно входит в `linux-firmware`. Не устанавливается неизвестный проприетарный драйвер и не меняются настройки ядра.

Проверка:

```bash
sudo bash deploy/boosty-video-deps check
ls -l /dev/dri/renderD*
ffmpeg -hide_banner -encoders | grep -E 'h264_vaapi|hevc_vaapi'
```

Для **Docker Compose**:

```bash
sudo env BD_VIDEO_ACCEL=amd bash install.sh --mode docker
# Для уже установленного сервера, при подготовленном драйвере:
# bdy restart  # сохранённый режим amd и группа render будут применены
```

Overlay открывает `/dev/dri` и предоставляет процессу контейнера GID группы render; ядро/прошивку следует настроить на хосте. Не используйте `privileged: true`, не пробрасывайте Docker socket, не передавайте весь `/dev`.

## NVIDIA (NVENC)

Установить **официальный драйвер NVIDIA**, проверить `nvidia-smi`; для контейнера отдельно установить [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html), настроить Docker runtime, затем:

```bash
sudo env BD_VIDEO_ACCEL=nvidia bash install.sh --mode docker
```

Нужно передать capability `video` — одного `compute` недостаточно. В панели выберите NVENC, H.264/HEVC и выполните пробное кодирование. Совместимость по кодекам зависит от поколения NVIDIA и сборки FFmpeg. Помощник `deploy/boosty-video-deps nvidia` устанавливает FFmpeg, **не переустанавливая видеодрайвер**.

## Intel Quick Sync и другие серверы

```bash
sudo bash deploy/boosty-video-deps intel
sudo env BD_VIDEO_ACCEL=intel bash install.sh --mode docker
# Для уже установленного сервера, при подготовленном драйвере:
# bdy restart  # сохранённый режим amd и группа render будут применены
```

В панели выбрать QSV; проверить пробное кодирование. Для CPU-only достаточно `ffmpeg` + `ffprobe`, дополнительно GPU и пакеты драйверов не требуются. На других Linux-дистрибутивах используйте системный менеджер пакетов и команду `boosty-video-deps check`.

**При работе в Docker GPU должен быть доступен внутри контейнера**; настройка в веб-панели не может автоматически пробросить устройство или установить пакет драйвера на хосте. Если проба не проходит, работоспособный CPU fallback выбирается автоматически только при включённом соответствующем флажке администратора.

## Управление

Настройки → Управление сервером → Видео и аппаратное ускорение. Администратор может включить обработку, выбрать backend и качество, сохранить ограничение размера, запустить диагностику и вручную поставить в очередь любой готовый архивный видеофайл. Аккаунтам без роли администратора endpoints `GET /api/admin/video` и `POST /api/admin/video/jobs/{id}` возвращают `403`.

**Безопасный стандарт**: обработка отключена; сырой оригинал остаётся единственной копией. Включение дополнительной версии **увеличивает** место на диске, если сохранять и оригинал; опция «только уменьшившиеся файлы» предотвращает бессмысленное расходование пространства, но при ней не получится получить совместимую версию, если она больше оригинала. Перед массовой обработкой проверить свободное место и создать резервную копию.

## Что проверить на реальном оборудовании

- [ ] VA-API H.264 и HEVC на реальном 5600H/Vega 7, версии Mesa/FFmpeg, права `render`, размеры и энергопотребление.
- [ ] NVIDIA NVENC в native и Docker, использование `nvidia-smi` и правильный Toolkit/runtime.
- [ ] Intel QSV в native и Docker; результаты старых и новых платформ отличаются.
- [ ] Заполненный диск, отключение GPU посреди обработки, сильные сбои FFmpeg, тесты fallback.
- [ ] Задания с HLS/DASH после добавления полноценной скачки всех сегментов, потоковый HLS-плеер.
- [ ] Фоновая очередь на десятках/сотнях видео: дисковые квоты, планирование нагрузки, пауза, отмена, ограничение одновременных процессов и приоритетов.
