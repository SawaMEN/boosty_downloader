# Архитектура

Boosty Downloader — одиночный Go-сервис с веб-панелью и очередью фоновых задач. Его можно запустить напрямую через systemd или внутри Docker Compose.

## Компоненты

| Компонент | Реализация | Ответственность |
| --- | --- | --- |
| HTTP API и UI | `internal/server/` | Авторизация, медиатека, управление заданиями |
| Клиент Boosty | `internal/boosty/` | Доступные публикации, подписки и метаданные |
| Загрузчик/обработка медиа | `downloader.go`, `hls*.go`, `dash.go`, `video.go` | Получение файлов, HLS/DASH, FFmpeg |
| Storage | `storage.go`, `revisions.go`, `dedup.go` | JSON-состояние, файлы и история |
| SQLite (эксперимент) | `sqlite_*.go` | Проверка, зеркало и офлайн-переиндексация |
| Установка и обновления | `install.sh`, `deploy/` | systemd, Docker, TLS, проверка запуска |

## Границы безопасности

- Каждый пользователь имеет свои учётные данные Boosty и свои архивы. Наличие одного физического медиафайла через hardlink **не** означает общего доступа.
- Разрешения на HTML, ZIP, медиа, изменения и удаление проверяются сервером. Анонимные пользователи не получают общий архив.
- Веб-процесс работает без полномочий root. Управление пакетами ОС, systemd и Docker выполняет только отдельный установщик или root-owned updater.
- Секреты и TLS-ключи не должны попадать в Git, логи или Docker socket.
- JSON — основной источник состояния. SQLite Shadow не авторизует пользователей.

## Модель хранения

```text
/etc/boosty-downloader/       конфигурация, TLS и ключ
/var/lib/boosty-downloader/   jobs.json, imports.json, accounts.json
                              library/<owner>/<author>/<post>/
                              revisions/<owner>/<author>/<post>/<revision>/
                              blobs/sha256/...
```

Файлы и права владельцев не должны смешиваться при дедупликации. История версий ограничена, удаление должно учитывать ссылки других владельцев.

## Развёртывание

Native использует `boosty-downloader.service`, Docker — изолированный контейнер Compose с данными через volume. Оба режима используют одинаковые постоянные каталоги. HTTPS обязателен.
