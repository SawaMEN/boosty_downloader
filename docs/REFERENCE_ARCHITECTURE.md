# Источники проектирования: не только загрузчик и не только плеер

Дата обзора: 10 ноября 2026 года. Это постоянно обновляемая таблица решений для **всего Boosty Downloader Web**: пользователи, публикации, комментарии, медиа, поиск, обновления, хранение и развёртывание. Ссылки ведут на оригинальные открытые проекты. Пометка «реализовано» означает наличие кода и локальных тестов, но не полноценный E2E на действующем Boosty.


> **Обязательная трассировка:** подробный список из 22 конкретных решений, с файлами источника, нашим кодом, статусом и критериями проверки — в [ROADMAP.md, раздел «Реестр заимствований и адаптаций»](ROADMAP.md#реестр-заимствований-и-адаптаций-из-проектов-источников-обязательный). Каждому новому интеграционному изменению присваивается `SRC-*`; одних названий WordPress/Orbita/Immich в документации недостаточно.

## Архитектурные правила, которые сохраняем при продолжении

1. **Один объект публикации, несколько представлений.** Сервер извлекает последовательность типизированных блоков поста. Та же модель используется живым просмотрщиком и автономным HTML-снимком. Отсутствующий файл помечается явно, ссылка на исходный CDN с токеном не сохраняется в HTML.
2. **Архив — независимая копия.** HTML, медиа, метаданные и по выбору комментарии/прикреплённые файлы открываются с VPS без запросов к Boosty. Дата `archiveUpdatedAt` должна обозначать успешное обновление снимка, а не проверку новых постов или изменение прав.
3. **Разграничение прав в каждой операции.** Доступ к общим копиям — только у зарегистрированных пользователей, при явном разрешении владельца/администратора. Поиск не раскрывает приватные записи или секреты CDN; сервер проверяет доступ к HTML, ZIP и каждому медиа.
4. **Стабильный каталог.** Сервер ограничивает размер страницы, сортирует и фильтрует по автору/названию/статусу, показывает даты и неполноту архива. UI не должен выгружать тысячи записей за один запрос.
5. **Не обещать недостижимого.** Ограничения пагинации комментариев Boosty отмечаются как `partial`. HLS/DASH, повреждённые медиа и отменённые пользователем вложения не должны маскироваться под «полную копию».
6. **Серверная автоматизация, не cron веб-браузера.** Задания восстанавливаются после рестарта; проверка новых постов выбранных подписанных авторов управляется администратором. Дедупликация и квоты должны работать при нескольких аккаунтах.
7. **Безопасные обновления всего приложения.** Проверять подписи/хэши релиза; делать резервную копию конфигурации и метаданных; проверять health после перезапуска; уметь откатываться. Native и Docker используют одну схему данных, но разные механизмы обновления.

## Что НЕ переносим целиком

- WordPress является CMS, а не загрузчиком Boosty. Не переносить PHP, плагины, wp-cron, WordPress БД или сторонние платежи. Переносим **архитектурные принципы**: роли, REST ACL, ревизии, транзакционные обновления, медиатеку.
- Orbita — самостоятельная социальная/платёжная платформа. Не нужна её бизнес-логика подписок и платежей; полезны модель контента, права, комментарии, плеер, поиск и организация страниц.
- Настольный `lowfc/boosty_downloader` не рассчитан на многопользовательский VPS. Использовать **UX-идеи**, а не копировать код: его лицензия CC BY-NC 4.0 и дополнительные условия ограничивают повторное использование.
- Код WordPress преимущественно GPL; прямое включение его исходников в наш сервис нежелательно без отдельного лицензирования. `ath31st` и `wpt/b00p` имеют собственные лицензии; в этой итерации заимствуются идеи, а не куски исходного кода.
- Не делать публичный безавторизационный каталог чужих платных материалов. Предоставление доступа к посту на Boosty **не означает** право распространять копию; администратор должен учитывать авторские права.

## Список следующих технических этапов

### P0 — до реального использования
- [ ] E2E загрузки нескольких действительных постов: видео, изображения, комментарии, вложения, недоступный пост, истёкший токен.
- [ ] Полное сохранение видеопотоков HLS/DASH и воспроизведение локальной копии.
- [ ] Квоты пользователей/свободного места, retry/backoff и восстановление незавершённых задач.
- [ ] Нативная и Docker установка на VPS, переход между режимами, HTTPS, обновление и откат.

### P1 — качество всей площадки
- [x] Стабильная фильтрация и пагинация личного/общего каталога с серверной проверкой прав (без полной выгрузки в браузер).
- [x] Типизированные блоки в оригинальном порядке для живого просмотра и автономного HTML; отсутствие вложения отображается явно.
- [ ] Качественный rich-text Boosty/DraftJS, цитаты/ссылки/списки, аватары, даты и вложения комментариев.
- [ ] Корзина, история версий снимков и восстановление вместо необратимого удаления.
- [ ] Журнал действий администратора, журнал проверок авторов и уведомления пользователей.
- [ ] Панель ресурсоёмкости, размеры архивов, доля дедупликации, квоты.

### P2 — после стабилизации
- [ ] Поиск по полнотекстовому содержимому/комментариям, а не только по названию и автору.
- [ ] Умная фоновая переиндексация, миниатюры, избранное, прогресс просмотра и адаптивная мобильная медиатека.
- [ ] Плагины интеграций только после разработки явного интерфейса разрешений/изоляции.

**Принцип:** каждую завершённую функцию фиксировать в `docs/ROADMAP.md` и тестировать; наличие ссылки на источник не означает, что функция уже реализована.
