# Исследование и решения

Краткое обоснование архитектуры Boosty Downloader. Актуальный прогресс ведётся в [ROADMAP.md](ROADMAP.md); подробные исторические заметки не являются спецификацией для новых изменений.

## Задача

Сохранять **доступные авторизованному аккаунту** публикации Boosty и предоставлять приватный доступ к копии после загрузки. Основные сценарии: скачать файл, создать полный архив поста, импортировать публикации подписанного автора и делиться собственным архивом с выбранными зарегистрированными пользователями.

## Принятые решения

| Вопрос | Решение |
| --- | --- |
| Сервер | Go, встроенные HTML/CSS/JS, без отдельной БД для начальной установки |
| Развёртывание | Native systemd либо Docker Compose |
| Доступ | Отдельные пользователи, личные токены Boosty, HTTPS |
| Архив | Локальный HTML + манифест + медиа + история версий |
| Видео | Прямые файлы и ограниченная поддержка HLS/DASH VOD; FFmpeg для нужных преобразований |
| Хранилище | JSON как действующая база; отдельные архивы владельцев, SHA-256 и hardlinks |
| SQLite | Поэтапная миграция только после проверки ACL, файлов и отката |
| Обновления | Публичные релизы, контрольные суммы, изолированный root-owned updater |

## Ограничения, требующие проверки

- API Boosty, структура подписок и права на посты могут меняться.
- Комментарии, видео и HTML могут быть сохранены не полностью; пользователь должен видеть такой статус.
- DRM, live-видео и внешние защищённые плееры не поддерживаются как гарантированная функция.
- Массовые загрузки требуют испытаний на реальном VPS: объём диска, сроки действия CDN-URL, пропускная способность.
- Без тестирования нельзя считать миграцию SQLite или автоматический откат полностью безопасными.

## Сравнение с открытыми проектами

При проектировании изучались идеи [Immich](https://github.com/immich-app/immich) (медиа, фоновые задачи, GPU), [WordPress](https://github.com/WordPress/wordpress-develop) (обслуживание, обновления) и открытые загрузчики Boosty. Используются **архитектурные подходы**, а не готовый код этих проектов. Реализация собственная и подчинена модели доступа к публикациям Boosty.

Следующие действия и критерии готовности: [ROADMAP.md](ROADMAP.md).
