## Приоритетные задачи

1. [ ] **P0.** Публикация готовых бинарников и Ubuntu CI для установки одной командой **пройдены**. Остались проверка чистой Debian и выпуск стабильного `vX.Y.Z`.
2. [ ] **P0.** Пройти реальное E2E Boosty: открытые/закрытые посты, подписки, загрузки после истечения CDN-ссылки, разные медиа, комментарии.
3. [ ] **P0.** Проверки имитации аварий Native и Docker **пройдены в CI**: откат, `/healthz`, архивный файл, конфигурация и TLS. Остались реальный VPS, автоматический install-update и аварии на уровне диска.
4. [ ] **P0.** Защита открытия файлов и отрицательные тесты доступа **реализованы**: HTML, ZIP, медиа, HTTP Range, версии, симлинки и специальные файлы. Остались E2E восстановления, удаления и временных файлов на реальных архивах.
5. [ ] **P1.** Реализовать штатную синхронизацию SQL-индекса истории и медиа при сохранении файлов, без потери ACL.
6. [ ] **P1.** Безопасное переключение JSON → SQLite и обратно с блокировкой конкурентных записей, резервным снимком и испытаниями аварий.
7. [ ] **P1.** Улучшить поддержку сложных HLS/DASH, неполных комментариев и точность форматирования HTML.
8. [ ] **P2.** Браузерные E2E, нагрузочные тесты больших архивов и документация релиза 1.0.

## Последние проверки P0 (12.11.2026)

- [x] Общая блокировка обслуживания Native/Docker: установщик, root-updater, удаление и смена пароля не изменяют одну установку параллельно.
- [x] Обновление сохраняет сервер, `boosty-dbcheck` и идентификатор предыдущего релиза; rollback восстанавливает согласованный бинарник и проверяет `/healthz`.
- [x] **Аварийный CI для обоих режимов:** намеренно сломанный бинарник/контейнер → `bdy rollback` → сервис снова работает. Проверено, что архивный sentinel, конфигурация и TLS-ключи не изменились.
- [x] **Файлы и ACL:** сервер открывает архивные файлы через Linux `openat(O_NOFOLLOW)` с проверкой всех компонентов, а не по пути после `Lstat`. HTTP и ZIP работают с закреплёнными файловыми дескрипторами. Регрессионные тесты запрещают доступ к чужим версиям, симлинкам и FIFO и подтверждают HTTP Range.
- [ ] Реальная Debian/VPS: обновление, отказ при нехватке места, восстановление архива и токена после рестарта, продление Let's Encrypt.

**Приоритет P0: всего 4 крупных пункта, полностью закрытых 0, частично выполненных 3, не начат 1 (живой Boosty E2E).** В текущем защитном срезе **4 из 4 технических задач добавлены и проверены CI; на VPS остаётся 1 отдельная фаза испытаний**. Общая дорожная карта 13 этапов: 7 базовых выполнены, 6 остаются.

## SQLite: этап 12.3

- [x] **12.3.1** — офлайн JSON → SQLite, схема v1, тесты.
- [x] **12.3.2** — проверка целостности, владельцев, ACL и файлов; CLI `boosty-dbcheck`.
- [ ] **12.3.3** — транзакционный SQL-репозиторий реализован отдельно, но не включён в основной Storage и ещё требует интеграции.
- [ ] **12.3.4** — подготовительный мост: **4 из 6**, **2 осталось**.

В 12.3.4 уже присутствуют журнал восстановления `jobs.json` + `imports.json`, проверяемый бэкап метаданных, необязательное JSON → SQLite Shadow и офлайн-индексация медиа с SHA-256. **Рабочая база остаётся JSON**; реальный SQL cutover и аварийные E2E пока не выполнены.

## Критерии стабильного релиза

- CI проходит: Go + race detector, UI-проверки, Docker, amd64/arm64 и обе установки.
- Бинарники опубликованы в GitHub Releases с `SHA256SUMS`.
- HTTPS и система аккаунтов проверены; ни один пользователь не получает доступ к чужим данным.
- Живые публикации Boosty архивируются без ложных статусов «полностью сохранено».
- Резервное копирование, обновление и откат проверены на копии VPS.
