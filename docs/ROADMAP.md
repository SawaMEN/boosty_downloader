Актуально: 10 ноября 2026 года. Это живой технический план; выполненное отражает **реально внесённый код**, а не предполагаемую работоспособность с Boosty.

## Важные ограничения прототипа

- Не проводилось энд-ту-энд скачивание с действующей учётной записью Boosty; серверный API может меняться.
- У API комментариев встречаются ограничения на максимальное количество веток/ответов: приложение обязано отмечать частичный архив.
- В некоторых публикациях видео отдаются как HLS/DASH или через внешний плеер — текущий HTTP-проксирующий режим не превращает такой поток в MP4.
- Извлечение форматированного текста начальное, не гарантирует пиксельную идентичность оригиналу.
- Одна очередь и один worker на инсталляцию; лимиты хранения не реализованы. ZIP формируется потоково из разрешённых файлов архива.
- Установщик предназначен для Linux, systemd (native) и Docker Compose v2 (Docker), с приватного репозитория запускается из локального клона.
- Установки на реальный сервер и тестов Docker в контейнере разработки пока не было.

## Критерии готовности первой стабильной версии

1. `go test -race ./...` и `go vet ./...` проходят.
2. Native и Docker проходят тесты установки на чистой машине, с переключением без потери токенов и архивов.
3. Авторизованное и публичное скачивание работают на проверенных примерах Boosty.
4. Полный пост открывается без сетевых запросов к Boosty, а пропуски явно отражены в манифесте.
5. Неполные комментарии помечаются «частично», без ложного статуса полного архива.
6. Все пользовательские ссылки, медиа, HTML и операции с файлами проходят аудит безопасности.
7. Автоматическое продление сертификатов, восстановление очереди, безопасное обновление и откат проверены.

Исходное расширенное исследование помещено в `docs/RESEARCH.md`.

## Внедрено: каталог общих архивов

- Каждый владелец архива может опубликовать копию для **всех зарегистрированных** пользователей либо выдать точечные разрешения по логину. Публичных анонимных ссылок нет.
- Фильтрация общих архивов на сервере: `author` (частичное совпадение, без учёта регистра), `q` (автор, название поста, логин владельца).
- Проверка прав на HTML, ZIP, манифест и каждый медиафайл; изменение прав/удаление/повторное скачивание — только у владельца.
- Поле `archiveUpdatedAt` хранит время последнего завершённого снимка независимо от `updatedAt`; для старых архивов дата восстанавливается из манифеста или времени локального `index.html`.
- Юнит-тесты подтверждают приватность, выдачу прав всем, отзыв доступа, сохранение разрешений и корректную дату обновления.

## Требование: предложить архивы подписок сразу после подключения Boosty

Задача из диалога: при подключении пользователем своего аккаунта Boosty предложить создать полные локальные копии выбранных авторов, на которых он подписан. Фоновая загрузка начинается **только после явного подтверждения**, каждый пользователь работает исключительно со своим списком подписок.

- [x] Неофициальный `GET /v1/user/subscriptions` с `with_follow=true`, фильтрацией активных подписок, дедупликацией и постраничной загрузкой с проверкой offset.
- [x] Автоматически открывать окно с выбранными авторами **после подключения** через существующие методы `cookie` / `tokens`, без автозапуска скачивания.
- [x] Кнопки повторного открытия окна в разделах «Авторы» и «Аккаунт Boosty»; поиск, флажки, выбор всех/снятие выбора, счётчик и ограничение 20 авторов на одну операцию.
- [x] Настраиваемый предел публикаций на автора: 20 / 100 / все (до 2000 на импорт). Новые запросы к Boosty выполняются только после подтверждения списка.
- [x] Отдельная сохраняемая в `imports.json` очередь по авторам с прогрессом, статусами и продолжением после перезапуска. Найденные доступные посты переводятся в существующие индивидуальные задачи с дедупликацией.
- [x] Кнопка остановки поиска, проверка прав владельца, сохранение ранее поставленных в очередь постов.
- [x] Mock-тесты пагинации подписок, игнорируемого API offset, недоступных постов, повторного импорта, приватности и отмены; `go test -race`, `go vet`, `node --check`, HTML/UI contract-тест.
- [x] Исправлен жизненный цикл фоновых workers: остановка по контексту, закрытие приложения для тестов, восстановление задач.
- [ ] Проверить подписки и выдачу авторов на живом Boosty (свободные, платные, истёкшие, приостановленные, >100 авторов); подтвердить формат и пределы страниц.
- [ ] Проверить массовые загрузки на реальном VPS в обоих режимах установки, оценить свободное место, нагрузку и ошибки CDN.
- [x] Плановый мониторинг **новых** постов выбранных авторов: повторная проверка по расписанию, остановка на уже известной публикации, ручное включение/выключение, без дубликатов и накопления бесконечной истории. *Нужна проверка на реальном Boosty/VPS*.
