# Карта разработки Boosty Downloader Web

Актуально: 10 ноября 2026 года. Это живой технический план; выполненное отражает **реально внесённый код**, а не предполагаемую работоспособность с Boosty.

## Этапы (13)

- [x] **1. Каркас проекта.** Go HTTP-сервис, встроенный интерфейс, GitHub Actions, тесты.
- [x] **2. Начальные серверные установки.** Нативная сборка и systemd, Docker Compose; общие пути хранения и переключение режимов. *Реальный smoke-тест на VPS/Docker ещё нужен.*
- [x] **3. Основы безопасности.** HTTPS, пароль панели, секреты Boosty под AES-GCM, ограничение запросов и проверка URL. *Нужен дальнейший аудит.*
- [x] **4. Первый движок Boosty.** Метаданные поста, список медиа, выбор доступного качества, исходящая загрузка HTTP.
- [x] **5. Начальная выдача в браузер.** Проксирование файлов HTTP-потоком без постоянного сохранения.
- [x] **6. Начальное архивирование поста.** JSON, HTML, изображения, видео, аудио и вложения по выбору; просмотр через панель.
- [x] **7. Начальные комментарии.** Получение комментариев и ответов, маркировка возможного ограничения по данным API.
- [ ] **8. Проверка на реальном Boosty.** Бесплатный и платный посты, видео разного формата, токены, вложения, комментарии, ограничения VPS-IP.
- [ ] **9. Устойчивость архива.** Перепроверка хэшей/размера, повторное получение истёкших CDN-URL, отмена/повтор задач, ограничения диска и скорости.
- [ ] **10. Полная точность поста.** Корректный DraftJS rich-text, вложения комментариев, аватары, изображения вариантов, вложенные списки, исходный порядок и даты.
- [ ] **11. Дополнительные видеоформаты.** HLS/DASH, FFmpeg, внешние плееры с учётом прав доступа.
- [ ] **12. Экспорт и синхронизация.** ZIP, проверки полноты, обновление изменённых постов, фильтры и массовое скачивание, переносимый архив.
- [ ] **13. Выпуск 1.0.** Браузерные e2e, проверка native/docker на Debian/Ubuntu, обновления/откат, проверка автоматического HTTPS по домену и его продления, релизы и эксплуатационная документация.

## Важные ограничения прототипа

- Не проводилось энд-ту-энд скачивание с действующей учётной записью Boosty; серверный API может меняться.
- У API комментариев встречаются ограничения на максимальное количество веток/ответов: приложение обязано отмечать частичный архив.
- В некоторых публикациях видео отдаются как HLS/DASH или через внешний плеер — текущий HTTP-проксирующий режим не превращает такой поток в MP4.
- Извлечение форматированного текста начальное, не гарантирует пиксельную идентичность оригиналу.
- Одна очередь и один worker на инсталляцию; лимиты хранения и архива ZIP ещё не реализованы.
- Установщик предназначен для Linux, systemd (native) и Docker Compose v2 (Docker), с приватного репозитория запускается из локального клона.
- Установки на реальный сервер и тестов Docker в контейнере разработки пока не было.

## Критерии готовности первой стабильной версии

1. `go test -race ./...` и `go vet ./...` проходят.
2. Native и Docker проходят тесты установки на чистой машине, с переключением без потери токенов и архивов.
3. Авторизованное и публичное скачивание работают на проверенных примерах Boosty.
4. Полный пост открывается без сетевых запросов к Boosty, а пропуски явно отражены в манифесте.
5. Неполные комментарии помечаются «частично», без ложного статуса полного архива.
6. Все пользовательские ссылки, медиа, HTML и операции с файлами проходят аудит безопасности.
7. Автоматическое продление сертификатов, восстановление очереди, безопасное обновление и откат проверены.

Исходное расширенное исследование помещено в `docs/RESEARCH.md`.

## Полное ТЗ из обсуждения (зафиксировано в GitHub 10.11.2026)

**Статус:** нижеследующие пункты — требования к конечному продукту, а не утверждение, что они уже находятся в main. Части реализованы в рабочей копии и должны быть опубликованы и проверены отдельно. Все новые функции из обсуждения должны попадать сюда до продолжения разработки.

### A. Пользователи и вход в Boosty
- [ ] Сначала обязательная авторизация **в самом загрузчике**: отдельные аккаунты администратора и обычных пользователей, регистрация, вход/выход, сброс пароля, настраиваемое включение регистрации и антибрутфорс.
- [ ] После авторизации — **личное** подключение аккаунта Boosty, без общей учётной записи. Поддержать несколько доступных методов: ввод cookie/session-токена, импорт access/refresh/device ID, безопасный помощник извлечения авторизации; иные варианты входа только при проверенной совместимости, без сбора паролей Boosty на нашем сервере.
- [ ] Отключение Boosty с отзывом сохранённых токенов и возможностью оставить уже законно сохранённые локальные архивы. Смена Boosty-аккаунта не даёт доступа к чужим данным.
- [ ] Изоляция пользователя на **каждом** маршруте API, в архивах, ссылках скачивания, потоковом видео, ZIP, заданиях, комментариях, поиске и очередях. Роли admin/user и управление разрешениями.

### B. Первый вход: список подписок и выбор авторов
- [ ] Сразу после успешного подключения Boosty запросить список подписок текущего аккаунта (`/v1/user/subscriptions`, постраничный обход, `with_follow`); показать название, аватар, статус и автора.
- [ ] Предложить сделать копии: поиск/фильтры, выбрать всех/нескольких/ни одного, оценка объёма и количества публикаций, выбор лимита/диапазона; только **после подтверждения** создавать задания.
- [ ] Кнопка «Импорт авторов» для повторного запуска; пропуск дублей; отдельный прогресс каждого автора и всех загрузок; возможность отмены, повтора и возобновления после перезапуска сервиса.
- [ ] После первичного импорта — опциональное расписание проверки **новых/обновлённых постов** выбранных авторов без лишних запросов, с учётом доступного места и ограничений Boosty.

### C. Страница автора, поста и просмотр
- [ ] Медиатека с выбором автора → лента его постов → отдельная страница поста с исходным порядком блоков, метаданными и датами публикации/архива.
- [ ] Смотреть видео и слушать аудио прямо в посте, листать изображения, разворачивать дерево комментариев и ответы, скачивать отдельные файлы/вложения, не переходя на Boosty.
- [ ] Удобный мобильный и десктопный интерфейс: отдельные разделы «Авторы», «Мои архивы», «Общие архивы», «Загрузки», «Boosty», «Настройки»; поиск, сортировки, фильтры, состояние очередей и ошибки.
- [ ] Плеер: взять архитектурные идеи из `bezumkin/orbita` (Vidstack/HLS.js, адаптивный плеер, скорость, качество, полноэкранный режим, PiP, продолжение просмотра, клавиатура, ошибки). Решение о библиотеке принять по актуальному состоянию сопровождения и размеру зависимостей; предусмотреть MP4 HTTP Range, HLS, DASH при технической возможности и соблюдении прав.

### D. Полный автономный архив публикации
- [ ] По ссылке или из списка автора: «Скачать на ПК» потоком либо «Сохранить на VPS»; опции включения комментариев/ответов и прикреплённых файлов, видео/аудио, изображений.
- [ ] Полная копия — HTML + структурированный JSON + локальные медиа и файлы + манифест целостности и ошибок, пригодные для открытия **без Boosty и внешнего CDN**; опциональный ZIP для скачивания.
- [ ] Если часть комментариев/ответов Boosty API обрезает или не отдаёт, пометить архив **частичным**, указать получено/ожидалось и причину вместо ложного «100%».
- [ ] **Обязательная дата последнего успешного обновления архива** (отдельно от даты публикации и изменения прав); дата первой архивации, размеры, состав, состояние обновления, история/ошибки.
- [ ] Ручное обновление поста/автора, фоновое повторное получение файлов с истёкшими CDN-ссылками, проверка длины/хэшей, HTTP Range resume, атомарная запись .part, квоты диска и ограничение параллелизма.

### E. Раздача, поиск, удаление
- [ ] У каждого поста — приватный доступ по умолчанию; владелец может **поделиться с конкретными участниками** либо включить «Доступно всем зарегистрированным пользователям»; отзыв доступов.
- [ ] Пользователь ищет **общие архивы**, включая поиск **по автору**, заголовку и владельцу, с фильтрами/пагинацией и отображением даты обновления. Никаких анонимных общедоступных архивов по умолчанию.
- [ ] Содержимое общих копий (видео, комментарии, файлы, ZIP) доступно только в пределах явно выданных прав; редактирование и удаление — только владельцу, плюс отдельные административные полномочия, с аудитом действий.
- [ ] Удаление отдельного поста или **всех постов выбранного автора** с подтверждением, остановкой зависимых задач, безопасной очисткой ссылок/права доступа; не трогать чужие архивы. Можно предусмотреть корзину/отложенное удаление и освобождение занятого места.
- [ ] Если владелец отключает Boosty, не теряются уже сохранённые архивы и их разрешения; новую загрузку платного содержимого без действующих прав не выполнять.

### F. Установка, обслуживание, контроль качества
- [ ] Два равноправных варианта: **native systemd** и **Docker Compose**, по аналогии с `SawaMEN/Firewall-UI`, с едиными каталогами данных, миграцией между вариантами и без обязательного Node.js на VPS.
- [ ] Интерактивный установщик: локально/SSH, публичный IP или домен; HTTPS с готовым сертификатом, автоматическим выпуском/продлением там, где поддерживается, либо доверенный обратный прокси; обновление, резервная копия, откат, журнал, диагностика, полное удаление только своих данных после подтверждения.
- [ ] Публикация проверенных Linux amd64/arm64 бинарников и Docker-образов, CI для Go/JS/shell, native/docker smoke/e2e. Репозиторий сейчас **приватный**: `raw.githubusercontent.com/.../install.sh` без авторизации не работает; для установки использовать локальный клон или аутентифицированный канал релизов.
- [ ] Сквозные тесты на реальном аккаунте Boosty с разрешённым содержимым, тестирование потока/архива/комментариев, SSRF/XSS/CSRF, проверка прав доступа и потокового видео, нагрузка и недостаток места на VPS.
- [ ] Уважать авторское право и правила сервиса; подключение Boosty не означает автоматически право на публичную раздачу материала. Общий доступ — только к содержимому, которое пользователь вправе распространять.

### Рекомендованный порядок следующей работы
1. Опубликовать текущие локальные изменения и проверить наличие каждого файла в `main`.
2. Тестировать регистрацию, вход/выход, изоляцию и общие архивы на уровне API + UI.
3. Реализовать и проверить окно импорта подписок после подключения Boosty; фоновая очередь по авторам.
4. Отладить просмотр поста, комментарии, видео и файлы в единой странице.
5. Прогнать GitHub Actions и тесты Docker/native, затем живой Boosty smoke-test.

**Общая шкала:** 13 крупных этапов; первые 7 — начальная реализация, этапы 8–13 не закрыты. Прогресс подпунктов учитывается только после коммита и проверок, а не по сообщениям в чате.
