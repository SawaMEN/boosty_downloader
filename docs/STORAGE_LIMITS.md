# Место на диске и квоты

Настройки доступны администратору и применяются к новым файловым записям.

| Настройка | Значение по умолчанию | Диапазон |
| --- | --- | --- |
| `minFreeGiB` — оставить свободным | 1 ГиБ | 0 (выключено) или 1–1024 |
| `maxUserGiB` — ограничение на пользователя | 0 (нет лимита) | 0 или 1–16384 |

Использование пользователя считается **логически** по его библиотеке: физическая дедупликация не уменьшает его квоту. Доступный объём файловой системы проверяется непосредственно перед записью. При нехватке места новая запись прерывается, сохранённые файлы не должны удаляться автоматически.

Администратор видит использование через `GET /api/admin/storage`. Чужие токены и пароли в API не выдаются.

## Ограничения

- Квота не является атомарным бронированием всего свободного места: параллельные процессы и FFmpeg могут занять диск между проверками.
- Если установить лимит ниже существующего расхода, имеющиеся архивы сохраняются, новые записи блокируются.
- Не используйте симлинки в каталогах пользователя.
- Для строгой изоляции в многопользовательской среде нужны отдельные квоты файловой системы или cgroups.

Перед массовым импортом публикаций проверьте доступное место и [настройки хранения](STORAGE_COMPRESSION.md).
