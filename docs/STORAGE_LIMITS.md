# Место на диске и квоты

Настройки доступны администратору и применяются к новым файловым записям.

| Настройка | Значение по умолчанию | Диапазон |
| --- | --- | --- |
| `minFreeGiB` — оставить свободным | 1 ГиБ | 0 (выключено) или 1–1024 |
| `maxUserGiB` — ограничение на пользователя | 0 (нет лимита) | 0 или 1–16384 |

Использование пользователя считается **логически** по его библиотеке: физическая дедупликация не уменьшает его квоту. Доступный объём файловой системы проверяется непосредственно перед записью. При нехватке места новая запись прерывается, сохранённые файлы не должны удаляться автоматически.

Перед загрузкой медиа и перед публикацией обновлённого архива размер библиотеки пересчитывается с диска, включая метаданные и временные файлы. Временно существующие hardlinks считаются по каждому пути: обновление может потребовать большего логического лимита, чем итоговая библиотека. При отказе существующий архив остаётся на месте.

Администратор видит использование через `GET /api/admin/storage`. Поле `bytes` по-прежнему означает библиотеку; `revisionBytes` показывает историю версий отдельно, а `revisionError` сообщает о невозможности её измерить. История пока не включается в пользовательскую квоту, и её логический размер не равен дополнительному физическому расходу из-за hardlinks. Чужие токены и пароли в API не выдаются.

## Конкурентные фоновые операции

Архивирование и обработка видео одного владельца используют общий
отменяемый ограничитель. Следующая операция рассчитывает квоту после
завершения предыдущей. Разные владельцы могут работать параллельно;
коллизии 64 фиксированных групп иногда сериализуют разные аккаунты.
Готовая дополнительная видеоверсия проходит проверку квоты и резерва
перед публикацией. Читатели архива не захватывают этот ограничитель.

Для всех guardedCopy общий ограничитель процесса сериализует проверку
физического резерва и запись одной порции (до 256 КиБ), даже при выключенной
квоте у другого загрузчика. Чтение из сети не удерживает этот ограничитель.
Ожидание отменяется через контекст. Это не блокировка всего архива.
HLS/DASH remux и фоновые видеоверсии контролируют максимальный размер,
квоту и свободное место во время FFmpeg и после его завершения; при
превышении процесс прерывается, а временный результат не публикуется.

## Ограничения

- Общий ограничитель защищает только guardedCopy внутри одного процесса. FFmpeg, записи метаданных, другие процессы и округление до блоков файловой системы всё ещё могут уменьшить резерв между проверками. Опрос FFmpeg не является жёстким побайтовым лимитом.
- Если установить лимит ниже существующего расхода, имеющиеся архивы сохраняются, новые записи блокируются.
- Не используйте симлинки в каталогах пользователя.
- Для строгой изоляции в многопользовательской среде нужны отдельные квоты файловой системы или cgroups.

Перед массовым импортом публикаций проверьте доступное место и [настройки хранения](STORAGE_COMPRESSION.md).
