# Контроль диска и пользовательские квоты (этап 9)

**Источники:** `SRC-IMM-05` — Immich (ограничение фоновой нагрузки и времени жизни временных ресурсов), `SRC-WP-06` — WordPress (предварительные проверки перед потенциально опасными операциями), `SRC-7Z-01` — отдельная оценка физического и логического размера архива. Это собственная реализация на Go, исходники сторонних проектов не копируются.

## Настройки администратора

- **Минимум свободного места (`minFreeGiB`)**: 0 — выключить резерв; 1–1024 ГиБ. По умолчанию 1 ГиБ. Проверяется через `statfs` непосредственно перед записью; при недостатке пространства задача помечается как ошибочная/частичная и ранее сохранённые файлы остаются на месте.
- **Максимум на пользователя (`maxUserGiB`)**: 0 — без ограничения; 1–16384 ГиБ. По умолчанию отключено, поскольку размер библиотеки при первой установке неизвестен. Ограничение действует на аккаунт администратора тоже.
- **Учёт использования:** размер всех обычных файлов внутри `library/<user-id>`, включая частичные сегменты и производные копии. Это *логическая квота*: hardlink-дедупликация уменьшает физически занятое место, но каждый владелец оплачивает собственное логическое использование файла.
- **Реальный свободный объём** — из доступных процессу блоков файловой системы; он учитывает существующие данные других пользователей и приложений.
- **API** `GET /api/admin/storage` — только администратор, список пользователей и их логический размер; пароли, ссылки на Boosty и токены в ответ не входят.

Ограничения применяются к HTTP-загрузке обычных вложений, HLS, DASH, диапазонам и локальным копиям сегментов. Проверка выполняется до каждой порции записи, в том числе когда CDN не отправил `Content-Length`. Перед сборкой MP4 необходимо оставить запас для итогового файла. Места, занимаемые видеоконвертером FFmpeg, проверяются предварительно, но не заменяют файловые квоты ОС или cgroups: при наличии других одновременно работающих процессов нельзя считать расчёт строгой резервирующей транзакцией.

## Безопасность

- У пользовательских каталогов нет разрешённых символических ссылок. Недоступный каталог возвращает ошибку вместо «0 байт».
- Если администратор понизил квоту ниже существующего объёма, новые записи блокируются, существующие материалы не удаляются.
- Квоты не открывают пользователям новых прав. Проверки доступа к архивам выполняются существующими обработчиками.
- Не устанавливать компоненты ОС автоматически из HTTP-интерфейса. Изменение политики выполняется под администратором и сохраняется атомарно.

## Дальнейшие проверки
