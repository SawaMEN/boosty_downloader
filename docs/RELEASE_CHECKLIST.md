# Допуск стабильного релиза

Стабильный тег не создаётся автоматически. Автоматический gate проверяет
строгий формат vX.Y.Z, принадлежность коммита истории main и последний CI
события push для того же SHA. Ошибка API, отсутствие CI или неуспешная
проверка блокирует сборку. Preview остаётся отдельным каналом.

## Обязательные подтверждения перед v1.0.0

| Проверка | Подтверждение |
| --- | --- |
| Полный CI точного SHA main | Ссылка на успешный run |
| Debian 12/13 с systemd, Native и Docker | Отдельный тестовый VPS, журнал установки, /healthz |
| Обновление и rollback | Сравнение хешей архива, конфигурации и TLS до/после |
| Реальные доступные посты Boosty | Открытый, закрытый доступный, недоступный, комментарии, медиа |
| CDN и многопериодный DASH | Сохранённый файл, длительность, SHA-256 и честный partial |
| Параллельные загрузки и нехватка места | Отказ без повреждения предыдущего архива |
| Backup и restore | Восстановление в новый каталог и проверка ACL/хешей |
| AMD64/ARM64 и SHA256SUMS | Проверка четырёх бинарников и контрольных сумм |

Не помечать реальные проверки выполненными по синтетическим фикстурам.
Использовать отдельную копию VPS и собственный аккаунт Boosty. Не публиковать
токены, конфигурацию, ключи TLS, подписанные CDN URL и приватные архивы.
Откат бинарника не является откатом данных. См. UPDATES.md и DATABASE.md.

## Ограничения

Gate не подтверждает реальные испытания VPS/Boosty. Вручную подтвердить
таблицу до создания стабильного тега. JSON остаётся безопасным выбором
по умолчанию, экспериментальный SQLite-primary не объявляется production.
При провале CI стабильный тег не публиковать повторно до устранения причины.
