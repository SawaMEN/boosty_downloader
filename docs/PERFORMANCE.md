# Профилирование производительности Go

Запускать в чистой копии репозитория на тестовой машине с Go 1.23 или
новее и достаточным местом для временных SQLite-фикстур и профилей:

```bash
bash tools/profile_go.sh
```

Инструмент компилирует тестовый бинарник один раз. Он выполняет только
синтетические benchmark; не запускает сервер, не открывает порт pprof,
не обращается к Boosty и не читает рабочую базу или токены. Профили и
бинарник сохраняются в отдельном приватном временном каталоге, путь
печатается при старте. После анализа удалите этот каталог самостоятельно.

| Нагрузка | Сравнение |
| --- | --- |
| copy | Новый буфер против ограниченного пула |
| scheduler | Полная сортировка против ограниченного выбора, 100 000 записей |
| shadow | Полная материализация против потокового плана, 10 000 архивов |
| guard | Материализация против полной потоковой проверки, 10 000 архивов |

Для каждой нагрузки сохраняются три повтора без профилировщика
(`*.bench.txt`) и отдельный прогон оптимизированного варианта с CPU
и memory profiles. `*.cpu.txt` показывает CPU samples, `*.alloc.txt` —
выборочные аллокации, `*.heap.txt` — удерживаемую Go-heap память.
`environment.txt` фиксирует SHA, состояние рабочего дерева, Go,
архитектуру и GOMAXPROCS. Сравнивайте одинаковый SHA/Go, оборудование,
настройки и фоновые нагрузки; проверяйте медиану повторов, а не единичный
результат. Замеры с профилировщиком не сравнивайте напрямую с обычными.

```bash
go tool pprof -top -alloc_space /path/to/server.test /path/to/shadow.mem.pprof
```

Профили включают создание синтетических фикстур, работу тестового
раннера и GC. B/op и allocs/op — не RSS; inuse_space не включает всю
память SQLite, FFmpeg, ОС и файловый кеш. Эти замеры не доказывают
производительность реального CDN, длительную стабильность или расход
памяти рабочего сервера. Для этого нужны отдельно испытания с
разрешёнными публикациями на тестовом VPS, без изменения проверок
поколения, ACL, квот и восстановления.

Не публикуйте профили, собранные с реальными данными пользователей.
