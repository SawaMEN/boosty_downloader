# Хранение и сжатие

## Zstandard

Для крупных исходных JSON поста и комментариев используется Zstandard (`.json.zst`). Небольшие файлы или данные, которые почти не сжимаются, сохраняются обычным JSON. HTML, манифест и медиа остаются читаемыми без распаковки.

Администратор может выбрать уровень сжатия; изменение действует для следующих сохранений, не переписывает старые архивы. Native использует системный `zstd`, в Docker он входит в образ.

## Дедупликация

Идентичные медиафайлы могут физически храниться через SHA-256 и hardlinks в `blobs/sha256/`. Каждый архив при этом сохраняет собственные пути и **собственные права доступа**. Одинаковый файл не означает, что один подписчик получает контент другого.

Дедупликация экономит только при совпадении байтов. При отсутствии поддержки hardlinks файл хранится отдельно. Исходные файлы проверяются по размеру и хешу; симлинки не используются для выдачи медиа.

## Что важно учитывать

- Сжатие уже сжатых MP4 и JPEG обычно неэффективно.
- Перекодирование видео — отдельная задача с расходом CPU/GPU и дискового пространства.
- Логическая квота пользователя включает его собственные файлы даже при общей физической дедупликации.
- При очистке не должны удаляться медиа, на которые продолжают ссылаться другие архивы.
- Эффективность сжатия зависит от реального состава медиатеки; фиксированный процент экономии не гарантируется.
